# Decision Log

## 2026-05-28

- Built `syncro-story-flow` as a standalone Simple Workflow, not an agent. **Why:** user wants one command that orchestrates existing BMad Method Phase 4 and TEA skills; no new persona or reasoning style is needed.
- Command accepts a story id/key and applies to any story. **Why:** user asked for a general workflow reusable across all stories.
- Workflow halts after every stage for confirmation. **Why:** user wants one command to guide sequence but keep human approval between steps.
- TEA stages are optional gates. **Why:** ATDD, automation, review, and trace add value by risk, but should not block small/low-risk stories unless user chooses.
- Output is a workflow skill under `skills/syncro-story-flow`. **Why:** BMB config points new skills to `{project-root}/skills`, and `bmad-` prefix is reserved for official BMad skills.
- Hardened resume into Orient autodetection instead of relying only on user-provided resume labels. **Why:** user wants workflow to recover when interrupted and continue from evidence.
- Added explicit final commit gate, not automatic commit mid-flow. **Why:** repository rules require explicit commit approval and scoped inspection; story flow should prepare commit only after workflow evidence is complete.
