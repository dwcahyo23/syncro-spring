# Decision Log

## 2026-05-29 Build Session

- Classified as Simple Workflow because the orchestration is linear enough to keep in one `SKILL.md`, even though it coordinates many downstream skills.
- Named `syncro-correct-story` to mirror `syncro-story-flow` while making the correction/remediation intent explicit.
- Scoped the workflow to BMad Method Phase 4 correction plus TEA gates for stories that are already started, in review, or done but failing manual/frontend/backend/UI/UX validation.
- Rejected a new agent design; this should remain a workflow conductor that invokes existing BMad and TEA skills.
- Hardening decisions: block next-story advancement until remediation passes, never commit/push automatically, enforce project command shapes from `CLAUDE.md`, require MCP browser verification for UI claims, and prefer shadcn/Radix non-native controls over native form controls.
- No `customize.toml` emitted because project-specific Syncro guardrails should be fixed in the skill; users can fork or add project overrides later if needed.
- Hardened intake so free-form correction signals are treated as broad scope evidence, not literal one-bug instructions. Added Intake and Gap Scan before Correct Course to reduce repeated retrofits.
- Added optional WDS/UX and Party Mode lenses before Correct Course for broad UI/UX, workflow, domain-model, or cross-functional corrections.
- Hardened with Blind Inspection and Proxy User modes so the workflow can independently inspect running UI/code outside planning artifacts and surface messy layout, overflow, responsiveness, unfinished component, and interaction-quality gaps before Correct Course.
- Kept the artifact as a workflow skill, not a new standalone agent, because coordination with BMad/TEA is the durable behavior; specialized agents/lenses can still be spawned during inspection when useful.
