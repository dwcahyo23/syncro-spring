# Decision Log

## 2026-05-28

- Built `syncro-story-flow` as a standalone Simple Workflow, not an agent. **Why:** user wants one command that orchestrates existing BMad Method Phase 4 and TEA skills; no new persona or reasoning style is needed.
- Command accepts a story id/key and applies to any story. **Why:** user asked for a general workflow reusable across all stories.
- Workflow halts after every stage for confirmation. **Why:** user wants one command to guide sequence but keep human approval between steps.
- TEA stages are optional gates. **Why:** ATDD, automation, review, and trace add value by risk, but should not block small/low-risk stories unless user chooses.
- Output is a workflow skill under `skills/syncro-story-flow`. **Why:** BMB config points new skills to `{project-root}/skills`, and `bmad-` prefix is reserved for official BMad skills.
- Hardened resume into Orient autodetection instead of relying only on user-provided resume labels. **Why:** user wants workflow to recover when interrupted and continue from evidence.
- Added explicit final commit gate, not automatic commit mid-flow. **Why:** repository rules require explicit commit approval and scoped inspection; story flow should prepare commit only after workflow evidence is complete.

## 2026-05-29

- Hardened `syncro-story-flow` for auto long-run execution with stop points only for ambiguity, failures, risky actions, or commit/push gates. **Why:** user configured local allow rules and wants story development to proceed with fewer blocks while preserving safety gates.
- Standardized Syncro command shapes in `CLAUDE.md` and project scripts. **Why:** stable commands are easier to allow in Claude Code settings and reduce accidental permission prompts from equivalent command variants.
- Preferred Playwright MCP browser tools over native Playwright CLI for web verification. **Why:** user reports native Playwright is heavy; MCP gives lighter interactive UI evidence for Claude-driven testing.
- Added robust long-run automation guardrails to `CLAUDE.md`: PowerShell command shapes, standard ports, background servers, server reuse, script-fix fallback, env safety, and native Playwright restrictions. **Why:** user wants Syncro development to run automatically with fewer permission blocks while keeping risky actions explicit.
- Finalized explicit `auto phase 4 tea` mode with command examples, downstream prompt defaults, full TEA path, closeout status guidance, and missing-skill fallback. **Why:** user wants one command to drive BMad Phase 4 plus TEA without repeated confirmation stops.
- Resolved downstream soft conflicts in review and TEA checklists: no automatic prompt files in committed artifact paths, no hardcoded `npm run test:e2e`, no native Playwright CLI requirement. **Why:** Syncro automation should prefer stable project commands and MCP browser checks without creating extra permission or staging noise.
